# First beta testers

We have not established external adoption or usability. The first useful test is a small group of volunteers installing on their own supported machines. Do not send unsolicited invitations from the agent.

Ask each tester to:

1. Install the source or runtime ZIP without help from the original development machine.
2. Run doctor and the provider-free demo.
3. Select one public documentation origin and read it from their own MCP client.
4. In local Codex, check actual tool discovery in a fresh chat and try a research question without explicitly naming the skill.
5. Retrieve one source passage, try an unselected source, and compare two snapshots.

Record setup time, unclear instructions, successful/blocked/partial pages, tool discovery and whether automatic skill selection occurred. Never record keys, private source text or personal paths. Useful acceptance: all testers understand incomplete states and can retrieve evidence; failures become reproducible issues rather than success claims.

For GitHub release: select the intended owner/repository, publish only reviewed source and checksum-verified release assets, enable private vulnerability reporting if available, and wait for actual Windows/Linux CI results before claiming CI passes. GitHub publication and official plugin-directory submission are separate actions.
